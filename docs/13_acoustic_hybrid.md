# 13. Acoustic REF 기반 하이브리드 ANC 실행 계획

> 기준일: 2026-09-20. 확정된 목표·기존 구현과 검토 중인 외부 OMAP 결합을 구분한다.
> 개발·분석·테스트는 Docker 안에서만 수행한다. x86_64 PC는 CPU 이미지, ARM64 Jetson은 Jetson 환경을 사용한다.
> 이 변경의 소프트웨어 검증을 Jetson 지연 측정이나 덕트 감쇠 실험으로 해석하지 않는다.
> 위치별 실행 체크리스트는 [docs/14](14_pc_jetson_workplan.md). 코드·합성 시험·분석은 실행 가능한 Docker 환경에서 현장 작업과 병행한다.

## 1. 확정된 목표와 실행 범위

- 기존 Jetson AGX Orin과 기존 덕트를 유지한다.
- 외부 소리를 실제 REF 마이크로 받아 제어하는 `reference=mic`이 필수다.
- ERR 마이크 한 점에서 저역과 **1 kHz 이상 고역을 모두** 감쇠시키는 것이 목표다.
- Jetson의 우선 개선 대역은 **1000–1600Hz**다. 시스템 전체 저역을 보존하고 800–1000Hz 경계도 따로 확인한다.
- 환경소음·기계음뿐 아니라 음성·음악도 상쇄한다. 음성 보존 손실을 사용하지 않는다.
- 목표 범위는 ERR 한 점이다. 한 점의 감쇠를 덕트 단면 전체의 quiet zone으로 확대하지 않는다.
- **현재 마이크와 USB DAC까지 모두 유지한다.** 하드웨어 교체·구매·공통 클록 장치 통합은 이번 범위에서 제외한다.
- `~/anc_project`는 읽기 전용이다. Jetson 시스템 설정·전원 모드 등 sudo가 필요한 시스템 변경은 금지다.
- 소리가 나는 측정·실행은 사용자 입회와 볼륨 최소 상태에서만 하며 항상 ANC OFF로 시작한다.

`digital-ref`의 재생 선행 정보는 acoustic REF의 대체물이 아니다.
기존 digital-ref 학습과 실험 결과는 별도 이력으로 보존하고 acoustic 기준선을 새로 만든다.
DSP FxNLMS의 10dB 이상 감쇠는 같은 덕트 구조·스피커이지만 다른 마이크를 쓴 사용자 보고다.
음원·대역·측정 조건이 미확인이라 Jetson과 직접 비교하지 않는다. 두 장치의 출력 합산 방식은
아직 미정이며, 아래 Jetson 내부 하이브리드를 외부 DSP 통합 구현으로 해석하지 않는다.
Jetson 마이크 교체 지시는 없고, 기존 800–1600Hz 연구 결과도 과거 기록으로 보존한다.

### 1.1 검토 중인 OMAP 저역 / Jetson 고역 분담

사용자는 1 kHz를 경계로 저역을 OMAP-L138 FxNLMS, 고역을 Jetson Orin으로 제어할 계획이다.
정확한 전이대역·필터·출력 합산 방식은 아직 정하지 않았다. 1000–1600 Hz는 첫 검증 우선대역이지
1 kHz 이상 전체 목표의 상한이 아니다. 기존 `HybridEngine`은 한 Jetson 내부의 파형 합산이며,
외부 OMAP과의 주파수 분할·오디오 전송·클록 정렬을 구현한 것이 아니다.

Windows CCS와 XDS200은 OMAP 개발·디버깅에 유지한다. JTAG 메모리 회수와 장치 간 실시간
오디오 전달은 다르다([수집 안내](DATASET.md)). USB–AUX가 USB 오디오 인터페이스를 뜻한다면
그 LINE OUT → 상대 장치 LINE IN은 아날로그 전달 후보지만, 단순 USB 케이블이나
출력 전용 동글이 양방향 PCM 통신을 제공하는 것은 아니다. 실제 동글 모델·입출력 레벨은 미확인이다.
LCDK에는 LINE IN/OUT이 있지만 사용자의 실물 보드 모델은 아직 확인하지 않았다.
[TI LCDK 하드웨어 안내](https://www.ti.com/lit/ug/spruil2a/spruil2a.pdf).

원본 `FxNLMS0/ISR.c`는 LINE IN의 L/R을 REF/ERR로 사용한다. 여기에 Jetson 상쇄음을
입력하면 현재 마이크 채널과 충돌하며, 펌웨어가 자동으로 저역 출력과 합산하지 않는다.
먼저 상쇄 스피커 한 개로 합칠지 각 장치가 별도 스피커를 쓸지, REF/ERR을 공유할지 확인한다.
출력끼리 직결하거나 Y 케이블로 합치지 않는다. 추가 DAC/ADC·버퍼 지연과 gain을 포함해
실제 경로의 S/F·고역 신뢰대역·시간 여유를 검증한다. OMAP의 16 kHz FIR을 Jetson의
48 kHz 또는 새 합산 경로 모델로 그대로 쓰지 않는다. 주파수 분담 자체가 인과 지연을 해결하지 않는다.

분담 구상은 원본 펌웨어 변경·보드 로드·오디오 출력 승인이 아니다. 초기 ANC-OFF 동기 녹음은
원시 REF/ERR을 보존한다. 추후 FxNLMS만 ON 또는 두 장치 ON으로 얻은 잔류음을 ANC-OFF
자료와 혼합하지 않으며, 별도 세션·조건으로 평가한다.

## 2. 먼저 확인할 세 가지

| 항목 | 확인할 증거 | 부족할 때 다음 작업 |
|---|---|---|
| 시간 여유 | REF가 ERR보다 소리를 먼저 관측하는 시간, S 경로 지연, 실제 핸드오프 | 고정 장치의 지연·지터 재검증, 사용자 공간의 처리/큐 지연 분석 |
| 고역 경로 | 우선 1000–1600Hz 전체에서 S의 반복 일관성·위상·SNR·출력 여유 | 기존 장치에서 광대역 재측정 및 레벨별 진단 |
| REF 오염 | CS 출력이 REF에 들어오는 피드백 경로 F | 별도 식별 후 보상 필요성 판정 |

모델을 크게 만드는 작업은 이 세 조건이 확보되는지에 따라 결정한다.
특히 과거 S의 신뢰대역 150–600 Hz는 1 kHz 이상 검증을 통과했다는 근거가 아니다.
자극을 보낸 대역과 반복 측정으로 검증된 대역을 구분한다.

## 3. 경로와 지연의 규약

| 기호 | 의미 | 제어에서의 역할 |
|---|---|---|
| S | 상쇄 출력 CS → ERR | filtered-x 계산과 출력의 실제 효과 모델 |
| F | 상쇄 출력 CS → REF | REF에 섞이는 자기 상쇄음의 피드백 모델 |
| 외부 소리 → REF/ERR | 동일 외부 소리를 두 마이크에서 관측한 경로 | 선행 시간·상관성·목표 잔류음 평가 |
| 기존 digital P | 내부 소음 출력 NS → ERR | 기존 digital-ref 실험용 경로 |

S와 F는 도착 위치가 다르므로 같은 필터로 취급하지 않는다.
초기 FxNLMS는 **사전에 측정한 S를 고정**하고 제어 FIR의 계수만 온라인으로 갱신한다.
이 계수 적응은 온라인 S 식별이나 F 식별이 아니다.

현재 3스레드 구조의 지연 비교는 다음과 같다.

```text
필요한 제어 경로 지연 = S NPZ의 순수지연 + 실제 런타임 핸드오프
사용 가능한 선행 시간 = 외부 소리의 REF → ERR 관측 시간차
인과 여유 = 사용 가능한 선행 시간 − 필요한 제어 경로 지연
```

두 항을 같은 샘플레이트·시간 기준으로 계산한다. S에 포함된 I/O나 음향 지연을 다시 더하지 않는다.
기하에서 얻은 REF→ERR 시간은 예비 추정이며 반사·클록 변동을 포함한 실측 증거를 대체하지 않는다.
현재 구현의 핸드오프는 한 hop이다. FIR 도입만으로 이를 0으로 설정하지 않는다.
인과 여유가 음수면 광대역의 예측 불가능한 성분을 일반적으로 상쇄할 수 없다.
주기 성분의 예측 가능성으로 얻은 감쇠를 음성·음악·대역잡음 전체의 성능으로 확대하지 않는다.

극성 규약은 계속 `e = d + S·y`이다. 측정 FIR에 극성이 포함되므로 부호를 추가 반전하지 않는다.
S 경로 측정값, 핸드오프, 샘플레이트의 단일 출처는 기존 설정·NPZ 규약을 유지한다.
약 1.6 kHz 평면파 차단 주파수는 단면 전체 제어와 모드 해석의 경계다.
**ERR 한 점 감쇠의 절대 상한은 아니다.** 그 이상도 위치 고정 상태에서 별도로 측정한다.

## 4. 이번 구현과 아직 남은 부분

이번 소프트웨어 작업은 다음 경계까지 진행한다.

- 외부 REF 모드에서 내부 소음 재생 여부가 FxNLMS 적응을 막지 않도록 조건을 분리한다.
- 내부 소음이 꺼진 acoustic 모드에서도 ANC OFF의 ERR 파워를 기준선으로 수집한다.
- `noise.enabled`로 내부 소음 출력의 초기 상태를 명시한다.
- acoustic 런타임에서 S 측정 당시의 블록 크기·latency 메타 누락/불일치와 샘플레이트 불일치를 거부한다.
- 출력 장치를 열지 않는 readiness 검사로 S·핸드오프·REF 선행 시간·고역 검증 범위를 확인한다.
- 기존 파형 DNN 출력과 FxNLMS 출력을 결합하는 초기 하이브리드 엔진 API를 마련한다.

`HybridEngine`의 초기 하이브리드는 **파형 출력 결합**이다. 장기 목표인 DNN의 FIR 계수 선택·생성은 미구현이다.
별도 연구용 `PreparedFxNLMSController`는 사전 기준 FIR + FxNLMS 잔차, 불변 제안/경계 교체/crossfade를 구현했다.
이는 live factory와 연결하지 않은 PC 오프라인 준비이며 학습된 선택기/생성기가 완성됐다는 뜻이 아니다.
논문 반영 범위·CPU 합성 비교·저장 ESS 진단은 [docs/15](15_prepared_fir_research.md)를 따른다.
학습된 계수 생성기, 온라인 S/F 추정, F 보상, 실측 비선형 모델도 아직 연결되지 않았다.
mic 모드의 DL/하이브리드는 `reference_mode=acoustic`으로 학습한 artifact만 허용한다.
기존 digital-ref 체크포인트와 reference 모드 정보가 없는 artifact는 시작 단계에서 거부한다.
readiness PASS도 장치 출력 허가나 감쇠 성능 판정이 아니다. 별도의 실기 검증이 필요하다.

## 5. 실행 순서와 단계별 산출물

### A. Docker 개발 환경과 준비 상태 검사

다음은 x86_64 PC용 예시다. 실제 ARM64 Jetson은 [Docker 안내](../docker/README.md)의 Jetson 절차를 따른다.
호스트에서는 Docker 환경만 관리하며, Python 실행과 파일 작업은 컨테이너에서 수행한다.

```bash
bash scripts/docker/dev.sh build cpu
bash scripts/docker/dev.sh up cpu
bash scripts/docker/dev.sh exec .venv/bin/python -m pytest -q
bash scripts/docker/dev.sh shell
```

코드는 `/workspace/Deep-ANC`에 바인드 마운트되어 수정이 원본 저장소에 반영된다.
`.venv`는 Docker volume으로 덮어 마운트한다. 기존 호스트 Python 환경은 보존하고 사용하지 않는다.
x86 CPU 컨테이너는 개발 공간이며 Jetson 에뮬레이션이나 GPU·오디오 실기 검증 환경이 아니다.
Jetson용 `build jetson`·`up jetson`은 실제 ARM64 Jetson에서만 실행한다.
기본 Jetson 이미지는 `nvcr.io/nvidia/l4t-jetpack:r36.4.0`과 NVIDIA PyTorch 2.5.0a0 wheel을 사용한다.
별도 경량 검증 환경과 기본 이미지의 완료 상태는 Docker 안내와 HANDOFF에서 구분한다.

기본 기준선 `configs/runtime_acoustic.yaml`과 S NPZ의 샘플레이트·지연·검증 대역을 대조한다.

```bash
bash scripts/docker/dev.sh exec .venv/bin/python scripts/bench/check_acoustic_readiness.py --json
bash scripts/docker/dev.sh exec .venv/bin/python scripts/bench/check_acoustic_readiness.py --require-band 1000 1600 --require-broadband
```

두 검사는 소리를 출력하지 않는다. 두 번째 검사는 우선 목표 1000–1600Hz 검증과 광대역 인과 여유를 요구한다.
첫 번째는 보고용이므로 exit 0을 광대역 준비 완료로 해석하지 않는다.
이 검증 구간의 상단 1.6 kHz는 이번 진단 범위이며 ERR 감쇠의 물리적 상한을 선언하는 값이 아니다.
REF 선행 시간은 기하 추정인지 실측인지 표시하고, 고역 검증 요구에 1 kHz 이상을 포함한다.
경로 파일 누락이나 고역 검증 부족을 0 지연·전대역 유효로 대체하지 않는다.
산출물은 준비 상태와 미충족 항목이며, 이것을 다음 측정의 입력으로 사용한다.

### B. Jetson 현장에서 입력만 확인

```bash
bash scripts/docker/dev.sh exec .venv/bin/python scripts/bench/check_audio_input.py --require-both --max-clip-ratio 0
```

오디오 장치가 연결된 Jetson 컨테이너에서만 수행하며 출력 장치는 열지 않는다. ERR와 REF 모두 반복해서 유효해야 한다.
입력 FAIL을 소리 출력으로 우회 진단하지 않는다. 이 실측은 오디오 장치를 연결한 실제 Jetson Docker에서 수행한다.
장치·배선·게인·볼륨·블록 크기·샘플레이트·측정 시각을 함께 기록한다.

### C. S를 먼저 측정하고 F를 별도로 확인

사용자 입회 상태에서 CS→ERR의 지연과 주파수응답을 측정한다.
저역과 1 kHz 이상을 포함한 반복 측정으로 신뢰대역을 정하고, 레벨별 THD/IMD도 확인한다.
동일 CS 출력의 REF 유입은 별도 F 경로로 기록한다. 기존 전달맵 도구를 진단에 활용할 수 있다.
단일 톤의 채널 확인만으로 광대역 S/F 식별이 끝났다고 판정하지 않는다.
원시 REF·ERR·출력 신호, 반복 측정 결과, xrun·클록 변동 기록을 함께 남긴다.

### D. 사전 측정 S를 사용하는 acoustic FxNLMS 기준선

`reference=mic`, `digital_reference_lead_samples=0`, `controller=fxlms`로 시작한다.
외부 소리만 평가할 때 내부 소음 출력은 `noise.enabled=false`로 둔다.
먼저 저레벨 주기 신호에서 극성·정렬·안정성을 확인하고, 이후 대역잡음·음성·음악으로 넓힌다.
S/F 경로와 지연 조건에 따라 제어 길이·적응률·출력 제한을 결정하며 과거 최적값을 그대로 확정하지 않는다.
ANC OFF에서는 적응하지 않는다. 페이드·입출력 클립·출력 누락 구간도 적응에서 제외한다.
입력 손상 후 FxNLMS는 S와 제어 FIR의 이력이 비워질 때까지 갱신을 중단한다.
mic DL/하이브리드는 손상 블록을 신경망에 넣지 않고 초기화하며 ANC를 페이드 OFF한다.
입력 복구 후 자동으로 ON이 되지 않으며 현장에서 다시 켜야 한다. 측정·녹음의 실제
유한 클리핑 값은 보존하고, 엔진에 전달할 입력만 차단한다.
초기화와 적응 상태 변경은 계수를 소유한 작업 스레드에서 수행한다.
산출물은 OFF→ON→OFF 원시 녹음과 밴드별 감쇠이며, 기존 실기 결과와 섞지 않는다.
runtime 녹음에는 S 해시·주요 설정과 전체 실행 누적 health 메타를 붙이며 기존 파일은 덮어쓰지 않는다.
회수한 녹음은 PC 또는 Jetson의 Docker에서 `scripts/eval/analyze_acoustic_session.py`로 사이클별 앞뒤 OFF와 비교한다.
긴 ON의 후반 악화와 1 kHz 이상 에너지 증가를 함께 보고한다. 이 수치는 관측 감소량이며
시간이 다른 외부 음원의 변화나 REF의 F 유입을 제거한 인과 효과가 아니다.
명령은 [docs/14 §5](14_pc_jetson_workplan.md), 통계·메타·한계는 [docs/07 §8](07_evaluation_protocol.md)를 따른다.

### E. 동일 조건에서 하이브리드 비교

설정은 `configs/runtime_acoustic_hybrid.yaml`이며 acoustic 학습 artifact 경로는 아직 placeholder다.
해당 artifact가 준비되기 전에는 이 설정으로 실기 성능을 평가할 수 없다.
또한 실제 DNN이 ERR를 입력으로 사용하면, 가중치를 고정해도 FxNLMS가 보는
폐루프 유효 경로는 단순 S와 달라질 수 있다. 현재의 고정 REF 전용 가짜 신경망
수렴 테스트는 그 되먹임 안정성을 검증하지 않는다. 실제 acoustic 모델의 독립
closed-loop 시험을 통과하기 전에는 하이브리드 배포 준비가 끝났다고 판정하지 않는다.
FxNLMS 기준선이 확보되면 동일한 S·출력 제한·소스·위치에서 초기 결합 엔진을 비교한다.
DNN을 더했을 때의 추가 감쇠, 최악 구간 증폭, 포화율, Jetson 처리시간을 함께 판정한다.
현재 파형 DNN이 핫패스에 있으므로 추론 시간은 여전히 출력 마감에 영향을 준다.
비교에서 이득이 확인되면 다음 단계인 필터 선택·생성 구조를 구현한다.

## 6. 장기 구조: 느린 계수 생성과 빠른 FIR

```text
REF·ERR 통계 + 측정 경로/레벨 조건 → 느린 DNN → 제어 FIR 계수 후보
현재 REF → 현재 제어 FIR → 상쇄 출력 → S → ERR
ERR + S를 통과시킨 REF → FxNLMS → 제어 FIR의 작은 보정
```

DNN은 과거·현재 관측으로 계수만 갱신하고, 빠른 경로는 마지막으로 검증된 FIR을 계속 사용하는 것이 목표다.
PC 연구 API에서 후보 유효성·출력 크기·교체 과도·단일 소비자 소유권·초기화 규약을 구현하고 합성 검증했다.
현재는 기준 FIR과 잔차를 분리해 유지하며 전환과 S/handoff 꼬리 동안 적응을 보류하는 실험 정책이다.
학습된 DNN 후보 생성과 실제 스레드 전달/오디오 연결은 아직 없으며 별도 안정성 리뷰가 필요하다.
이 구조는 CNN 프레임 계산을 출력 경로에서 분리하지만 I/O·핸드오프·음향 지연을 없애지 않는다.
비선형 확장은 실측에서 남는 왜곡을 설명하는 모델로 제안하고, 독립 레벨에서 개선을 검증한다.
합성 `tanh` 데이터 성능만으로 실제 스피커 포화나 고조파 상쇄를 주장하지 않는다.

## 7. 평가와 다음 의사결정

평가 지표는 [docs/07](07_evaluation_protocol.md)의 감쇠 부호·밴드·최악 구간 규약을 따른다.
저역과 1 kHz 이상을 나누고, 각 대역의 S 검증 여부·입력 SNR·실제 소스 에너지를 함께 표시한다.
환경소음·기계음·음성·음악별 중앙값과 최악 구간을 보고한다. 전체 평균만으로 성공을 판정하지 않는다.
외부 음원의 크기가 변하면 OFF/ON 차이에 그 변화도 섞인다. 재현 가능한 독립 반복을 확보한다.
소프트웨어 테스트 통과, x86 벤치마크, 과거 Jetson 측정, 신규 덕트 실측은 각각 출처를 표시한다.
특히 [docs/12](12_system_summary.md)의 수치를 이번 변경의 신규 실기 성능으로 인용하지 않는다.
인과 여유나 클록 안정성이 부족해도 현재 마이크·USB DAC를 교체하지 않는다.
실제 지연과 지터의 시간 기준을 재검증하고 Docker·사용자 공간의 처리/큐/핸드오프에서
줄일 수 있는 비용을 확인한다. 블록/latency를 바꾸어 시험한다면 해당 조건의 S를 다시 측정해야 한다.
사전 S 측정·FxNLMS 결합 자체를 지연 제거로 간주하지 않으며 달성 불가 대역/소스는 그대로 보고한다.
측정으로 유효성이 확인되기 전에는 설정의 지연이나 신뢰대역 숫자를 목표치로 바꾸지 않는다.

## 8. 참고 연구와 적용 한계

- [사용자 제공 논문, arXiv:2601.06981v1](https://arxiv.org/pdf/2601.06981v1): 방향 분류 CNN으로 미리 학습한 제어 필터를 선택하는 SFANC다. 4 REF/1 CS/1 ERR 구성에서 방향 선택을 다루며, 이 연구를 1 kHz 이상·비선형·Jetson 실기의 감쇠 검증으로 인용하지 않는다. 여기서 가져올 핵심은 CNN 프레임 계산과 빠른 FIR 출력을 분리하는 구조다.
- [Hybrid SFANC–FxNLMS, 2022](https://arxiv.org/html/2208.08082): 느린 CNN 선택과 샘플별 적응의 근거. 선형 경로 시뮬레이션이며 Jetson 실기 검증은 아니다.
- [GFANC, 2025 저자 구현](https://github.com/Luo-Zhengding/GFANC-Headphone): 계수 생성과 실시간 FIR 분리의 실제 헤드폰 구현. 노트북+PXI 결과이며 덕트/Jetson에 재검증이 필요하다.
- [Deep ANC, 2021 저자 전문](https://haozhang6720.github.io/doc/papers/Deep_ANC_2021.pdf): 비선형 스피커와 S를 통과한 잔류음으로 학습하는 근거. 예측 기반 지연 보상과 합성 비선형 결과는 현재 시스템의 물리 한계를 제거하지 않는다.

첨부 논문의 방향 분류기를 그대로 복제하는 것은 이 단계의 구현 범위가 아니다.
고정 덕트에서는 측정 경로·레벨 조건을 반영한 제어를 발전 방향으로 삼고, 효과는 위 순서로 검증한다.
