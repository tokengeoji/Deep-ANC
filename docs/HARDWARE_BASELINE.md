# OMAP-L138 실측 기준과 2차경로

사용자가 성공한 OMAP-L138 FxNLMS 실험을 딥러닝 준비의 기준으로 보존한다. Jetson Orin은 이 성공 실험에 참여하지 않았다. 아래 수치는 저장된 소스와 계수에서 확인한 값이며, 별도의 하드웨어 재측정 결과가 아니다. 소스 주석에 있는 감쇠 dB 수치는 성능 증거로 사용하지 않는다.

## 파일 역할

| 파일/프로젝트 | 역할 |
| --- | --- |
| [`rir.txt`](../rir.txt) | 정본 2차경로 `S_hat`, 원본 바이트와 계수 순서 유지 |
| [`FxNLMS0`](../firmware/omap_l138/FxNLMS0) | 성공한 실시간 ANC 소스: 256-tap 제어 필터, 500-tap 2차경로, 별도 500-tap feedback 경로 |
| [`NLMS0`](../firmware/omap_l138/NLMS0) | 취소 스피커에서 오류 마이크까지의 2차경로 측정 및 계수 출력 |
| [`NLMS1`](../firmware/omap_l138/NLMS1) | 기준 마이크에서 오류 마이크까지의 1차경로 측정 코드 |

`NLMS1` 코드가 있다는 사실만으로 측정된 1차경로 계수가 준비되었다고 간주하지 않는다. `F_hat`는 취소 스피커에서 기준 마이크까지의 feedback 경로이며, `rir.txt`의 `S_hat`와 다르다.

## 보존할 측정 정보

| 항목 | 값 |
| --- | --- |
| 샘플레이트 | 16,000 Hz |
| 계수 수 | 500 |
| 계수 표현 | `float S_hat[SEC_FILTER_TAP] = { ... };` |
| 계수 순서 | `h[0]`부터 `h[499]`, 인과적 FIR |
| 길이 | 500 samples = 31.25 ms; 마지막 tap의 지연은 499 samples |
| 최대 절댓값 위치 | zero-based index 49 = 3.0625 ms |
| 해당 계수 | +0.01850763 |
| 제곱합 | 0.00615059343307 |
| 계수 합 | 0.02882336 |
| 원본 SHA-256 | `9ece235a68a78a7f7c702d49d75525974df2ac2a8a9ca42ced155af901bcf9e3` |

원본의 500개 수치는 [`FxNLMS0/ISR.c`](../firmware/omap_l138/FxNLMS0/ISR.c)의 `S_hat` 500개 수치와 정확히 일치한다. peak 시각은 최대 계수의 위치일 뿐, 전체 경로 지연을 별도로 측정한 값은 아니다.

[`NLMS0/ISR.c`](../firmware/omap_l138/NLMS0/ISR.c)의 측정 정의는 다음과 같다.

```text
u[n] = 실제 DAC 출력 PCM16 / 32768
d[n] = 오류 마이크의 raw ADC PCM16 / 32768
d[n] ≈ sum(h[k] * u[n-k], k=0..499)
```

현재 ISR은 ADC를 읽고 새 출력 샘플을 만든 다음, 그 샘플을 `X[0]`에 넣어 적응한다. 따라서 계수의 앞부분과 지연에는 이 샘플 인덱싱, codec 및 음향 경로가 반영되어 있다. peak를 앞으로 옮기거나 앞부분을 제거하거나, 추정한 지연을 추가하지 않는다. 해당 측정 ISR에는 헤더 설명과 달리 소프트웨어 DC blocker가 없다.

계수를 최대값이나 에너지로 정규화하면 실제 입출력 gain이 바뀐다. 256 taps로 자르면 원본 에너지의 약 3.8823%를 버리므로 학습 기본값은 500 taps 전체로 유지한다. 16 kHz와 다른 샘플레이트를 사용하려면 명시적인 경로 변환과 검증이 필요하다.

## 실행 소스의 실제 기본값

[`FxNLMS0/ISR.c`](../firmware/omap_l138/FxNLMS0/ISR.c)의 실행 변수와 연산을 기준으로 한다. `define.h`의 일부 매크로와 헤더 주석은 아래 값과 다르며, 실제 ISR 기본값을 덮어쓰지 않는다.

| 항목 | ISR 기본값 또는 연산 |
| --- | --- |
| 기준 / 오류 마이크 | Left / Right (`ref_channel=1`) |
| 출력 채널 | 양쪽 동일 출력 (`speaker_channel=0`) |
| 출력 극성 | `inv_polarity=0`, `u=-y` |
| 적응률 / leakage | `mu=0.001`, `leakage=1.0` |
| feedback 제거 | 활성화, `fb_scale=1.0` |
| noise gate | 비활성화, threshold 0 |
| 입력 스케일 | PCM16 / 32768 |
| 입력 전처리 | 양쪽 마이크에 `z[n]=x[n]-x[n-1]+0.995*z[n-1]` |
| 출력 스케일 | `[-1,1]` 제한 후 `*32767`하여 PCM16 변환 |

`S_hat`는 signed plant 응답 그대로 유지한다. 제어기 출력 `y`를 사용하는 학습 정의라면 `u=-y`, `e=d+S*u=d-S*y`처럼 반전을 한 번만 적용한다. 모델이 DAC command `u`를 직접 출력하는 정의라면 잔차는 `e=d+S*u`이다. 학습과 평가에서 두 정의를 섞으면 안 된다.

FxNLMS 마이크 전처리와 NLMS0 측정의 raw ADC 영역은 다르다. 학습 데이터가 raw인지 DC 제거 후인지 기록하고, 잔차와 경로 출력에 필요한 전처리를 일관되게 적용한다. 이 차이를 보정하기 위해 정본 `rir.txt`를 임의 수정하지 않는다.

## 확인된 범위와 미확인 조건

세 프로젝트는 `CodecInit(..., WORD_LEN_16BIT, LINE_IN)`을 사용한다. 보존된 codec 소스의 LINE_IN ADC gain 기본값은 +3 dB, DAC volume 기본값은 0 dB다. 이는 코드 기본값이며, 측정 당시 외부 amplifier gain, 실제 연결, 스피커 위치, CCS에서 바꾼 실행 변수까지 증명하지 않는다. 이후 실험 기록에는 이러한 조건과 펌웨어 revision을 함께 남긴다.

Jetson에서 학습을 실행하는 것과 Jetson의 다른 오디오 장치로 실시간 제어하는 것은 경로 조건이 다르다. 이 RIR은 기존 OMAP 경로를 사용하는 학습 기준이다. Jetson이 직접 ADC/DAC를 담당하면 해당 장치·버퍼·출력 채널을 포함한 경로와 지연을 검증해야 한다. 기존 RIR의 peak 위치만으로 Jetson의 실시간 가능 여부를 판단하지 않는다.

신경망 학습의 수치 검증에는 impulse 응답의 gain·부호·시각, 인과성, convolution 경계, 출력 제한을 포함한다. PyTorch `conv1d`로 FIR을 구현할 때는 상관 연산의 특성을 고려하여 계수를 뒤집고 왼쪽에 499 samples를 padding한다. 실제 재생 출력의 제한과 같도록 학습/평가에서 스피커 출력 범위를 처리해야 한다.
