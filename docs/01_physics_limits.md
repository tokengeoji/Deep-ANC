# 01. 물리 한계와 지연 예산

현재 우선 모드는 acoustic-ref이며 Jetson 목표 대역은 1000–1600Hz다.
기존 Jetson·덕트·마이크·USB DAC를 유지한다. 이 문서는 목표와 별도로
측정 경로의 지연·신뢰대역이 허용하는 범위를 설명한다.
최신 작업 상태는 [HANDOFF.md](../HANDOFF.md), 성능 판정은 [docs/07](07_evaluation_protocol.md)를 따른다.

## 1. 채택한 측정 경로와 설정

아래 값은 저장소의 `assets/measured/{secondary,primary}_path_il.npz`와
[configs/duct.yaml](../configs/duct.yaml)을 기준으로 한다. 새 측정을 수행했다는 뜻은 아니다.

| 항목 | 값 | 출처·의미 |
|---|---|---|
| 샘플레이트 | 48,000Hz | P/S NPZ |
| 측정 블록 | 256샘플 | P/S NPZ의 calibration 메타 |
| S 순수지연 | 1465샘플 = 30.521ms | CS 출력 → ERR |
| P 순수지연 / `D_noise` | 1608샘플 = 33.500ms | 내부 NS 출력 → ERR |
| 런타임 핸드오프 | 256샘플 = 5.333ms | `secondary_path.handoff_extra_samples` |
| 제어 경로 총지연 | 1721샘플 = 35.854ms | S 순수지연 + 핸드오프 |
| P/S 반복 검증 대역 | 150–600Hz | `consistency_band_hz` |
| 반복 일관성 | S 약 0.956 / P 약 0.973 | NPZ의 `coherence_median` 필드 |
| 자극 대역 | S 72–1640Hz / P 64–1648Hz | 자극을 보낸 범위이며 검증 대역과 다름 |

P/S는 같은 capture에서 얻은 내부 스피커 경로다. 이 P를 외부 소리→REF/ERR 경로나
CS→REF 피드백 경로 F로 취급하지 않는다. acoustic 제어에서 S와 F의 역할은
[docs/13](13_acoustic_hybrid.md)을 따른다.

위 표는 기존 NPZ 메타데이터 기준이다. interleaved 측정 도구의 합성 round-trip에서
pre-roll만큼 추가 지연되는 미해결 문제가 확인됐다([HANDOFF §3](../HANDOFF.md)).
원시 capture와 저장 규약을 재검증하기 전까지 이 표를 새로 확정한 실측 지연으로 인용하거나,
기존 NPZ에서 pre-roll을 임의로 빼서 보정하지 않는다. OMAP 16 kHz `rir.txt`는 별도 경로다.

S 지연에는 측정 경로의 I/O·버퍼·음향 지연이 포함되어 있다. 같은 성분을 다시 더하지 않는다.
CS→ERR의 기하상 전파 시간은 약 0.146ms로, S 전체 지연과 구분해야 한다.

## 2. 기하로 계산한 선행 시간

`duct.yaml`의 위치와 음속 343m/s를 사용한다.
ERR 위치는 잠정값이며 반사·장치 클록·실제 도착 시각을 검증한 값이 아니다.

| 구간 | 거리 | 전파 시간 | 48kHz 환산 |
|---|---|---|---|
| NS → REF | 0.100m | 0.292ms | 약 14샘플 |
| REF → CS | 0.950m | 2.770ms | 약 133샘플 |
| CS → ERR | 0.050m | 0.146ms | 약 7샘플 |
| REF → ERR | 1.000m | 2.915ms | 약 140샘플 |
| NS → ERR | 1.100m | 3.207ms | 약 154샘플 |

## 3. Acoustic-ref: 현재 우선 모드

실제 REF 마이크의 관측을 제어 입력으로 사용한다. 외부 소리의 원본이나 미래 샘플은
입력으로 사용할 수 없으며 `digital_reference_lead_samples=0`이다.

```text
제어 경로 지연 = S NPZ 지연 + 런타임 핸드오프
선행 시간     = 같은 외부 소리의 REF → ERR 관측 시간차
인과 여유     = 선행 시간 − 제어 경로 지연

현 설정의 예비 계산:
2.915ms − 35.854ms = −32.939ms
```

약 32.9ms는 현재 기하 추정에 따른 예측 부담이다. 실제 REF/ERR 도착 시간·지터를
같은 시간 기준으로 측정해야 확정할 수 있다. FIR 도입이나 신경망 연산 단축만으로
측정 S 지연 또는 한 hop 핸드오프를 0으로 설정하지 않는다.

| 소리 성분 | 해석 |
|---|---|
| 안정적인 톤·고조파·반복 성분 | 과거 관측에서 예측할 여지가 있다. 주파수 변화·경로 오차·포화까지 포함한 실측이 필요하다. |
| 협대역·준정상 성분 | 예측 지평 동안 유지되는 상관성에 따라 감쇠 범위가 달라진다. |
| 예측 불가능한 광대역 성분 | 인과 여유가 음수인 현 경로에서는 일반적인 완전 상쇄를 기대할 수 없다. |

이 한계가 저역·고역과 음성·음악을 모두 평가해야 한다는 목표를 없애지는 않는다.
소스·대역별 결과와 실패 조건을 기록하고, 주기음 성공을 모든 소리의 성공으로 간주하지 않는다.
현재 장치를 유지하면서 실제 지연·지터와 사용자 공간의 처리·큐 비용을 검증한다.
블록 크기나 latency 조건을 바꾸면 그 조건의 S를 다시 측정해야 한다.

## 4. Digital-ref: 별도 비교·학습 경로

Jetson이 직접 생성한 소스를 모델에 먼저 공급하고 실제 NS 재생을 FIFO로 늦출 수 있다.
이 선행 공급은 acoustic-ref의 대체물이 아니다. 같은 출력 장치라는 사실만으로
측정 지연을 임의 소거하지 않고, 실제 P/S와 핸드오프로 정렬한다.

```text
lead = (S_delay + handoff) − D_noise
     = (1465 + 256) − 1608 = 113샘플

reference[t] = playback[t + lead]
reference에 대응하는 d 도착 = lead + D_noise = 1721샘플 뒤
reference로 만든 y 도착     = S_delay + handoff = 1721샘플 뒤
```

현재 `configs/data_sim.yaml`의 값은 113이다.
`configs/runtime_tiny.yaml`에는 **과거 ONNX 메타와의 호환용 109**가 남아 있다.
이는 이전 S=1342, D_noise=1489, 총지연=1598 구성에서 나온 값이며
현재 측정 정렬과 혼용하지 않는다. `runtime.yaml`의 lead=0도 배포용 정렬 완료를 뜻하지 않는다.
checkpoint/ONNX의 lead와 런타임 설정이 다르면 시작 전에 거부한다.

digital 학습의 P 선택은 다음과 같다.

| `digital_primary_path_mode` | 의미 |
|---|---|
| `measured` | 설정된 실측 P의 FIR·gain·순수지연 사용 |
| `secondary_surrogate` | S의 FIR·gain을 P 대용으로 쓰고 `D_noise`를 적용하는 표현 사전학습 |
| `rir_surrogate` | 합성 RIR 기반 비교 경로 |

현재 저장소에는 실측 P가 있지만 `data_sim.yaml` 기본 모드는 여전히
`secondary_surrogate`다. P 파일 존재와 실제 해당 모드의 학습 완료를 구분한다.
surrogate dB는 실제 덕트 감쇠나 FxLMS 대비 우위를 입증하지 않는다.

합성 RIR에는 음향 온셋이 이미 포함된다. digital RIR에 `D_noise`를 결합할 때는
NS→ERR 음향 온셋을 빼서 전기·버퍼 성분만 추가한다.
실측 P와 S의 compact FIR/순수지연에는 같은 보정을 중복 적용하지 않는다.
digital의 d 경로에는 제어 스레드 핸드오프를 붙이지 않는다.

## 5. 주파수와 평가 범위

평면파 차단 주파수는 `343/(2×0.105) ≈ 1633Hz`다.
이는 고차 모드와 단면 전체 제어를 논할 때의 경계이며,
**ERR 한 점 감쇠의 절대 상한은 아니다**. 한 점의 결과는 위치를 고정하고 따로 측정한다.

세 가지 대역을 구분한다.

- **사용자 목표:** 시스템 저역·고역 동시 감쇠, Jetson 우선 1000–1600Hz.
- **측정 신뢰대역:** 현재 S/P의 150–600Hz. 고역 검증은 아직 필요하다.
- **기존 학습 가중 설정:** `duct.yaml`의 80–800Hz. 이 값은 전체 프로젝트 목표가 아니며
  trusted NMSE는 S 신뢰대역과의 교집합인 150–600Hz다.

목표 대역을 설정하거나 합성 데이터에 고역을 넣는 것만으로 측정 신뢰대역과
손실의 검증 범위가 넓어지지 않는다. 저역·800–1000Hz 경계·1000–1600Hz·전체 대역,
음성·음악을 포함한 소스별 결과를 함께 보고한다.
검증 조건과 독립 반복 없이 과거 학습·벤치마크 수치를 신규 실기 성능으로 인용하지 않는다.
