# 12. 시스템 요약 — 목표·구성·검증 기준

현재 작업·실행 결과의 단일 기준은 [HANDOFF](../HANDOFF.md)다. 이 문서는 시스템의 역할과
판정 기준을 정리한다. 과거 학습·실험·지연 수치를 현재 환경의 검증 결과로 반복하지 않는다.

## 1. 목표와 유지 조건

최우선은 **acoustic-ref**다. 실제 REF 마이크가 받은 외부 소리로 제어하며 원본 음원이나
미래 샘플을 제어 입력으로 사용하지 않는다. 성공은 ERR **한 점**에서 판단한다.

- 저주파와 고주파를 모두 감쇠한다. 한쪽 대역만 성공하면 전체 목표 미달이다.
- 소음뿐 아니라 음성·음악을 포함한 모든 소리를 줄이는 quiet zone이 목표다.
- 고주파는 1 kHz 이상이며, Jetson의 우선 개선 대역은 **1000–1600 Hz**다.

Jetson AGX Orin·덕트·현재 마이크·USB DAC를 유지한다. RT 커널·30W 전원 모드·핀/I²S·
클록·오디오 서비스 등 호스트 시스템 설정을 바꾸지 않는다. 사용자 보고의 DSP FxNLMS 실험은
같은 덕트 구조·스피커와 다른 마이크를 사용했으므로 현 Jetson 구성의 직접 비교 결과가 아니다.
DSP/Jetson 출력 합산·스피커 공유·채널 배선은 아직 확정되지 않았다.

## 2. 환경과 역할

| 구성 | 역할·경계 |
|---|---|
| 실제 Jetson AGX Orin, L4T R36.4.4 | ARM64/CUDA/TensorRT 실행과 현장 실측 |
| Docker 개발 환경 | 모든 코드 읽기·수정·Python·테스트 실행; 호스트는 Docker 관리만 |
| `jetson-local` | CUDA 이미지와 전용 venv, 같은 호스트 cuDNN/TensorRT의 읽기 전용 연결 |
| x86 CPU Docker | 코드·합성 회귀·오프라인 분석; Jetson GPU/오디오 결과로 보고하지 않음 |
| Google Drive | 데이터 원본의 최종 보관소; 업로드 확인 후 임시 PC 원본 정리 |

이미지 빌드·패키지 설치·무오디오 스택 진단·프로젝트 모델 검증의 결과는 각각 기록한다.
이미지 빌드 성공으로 나머지 단계를 대신하지 않으며 최신 결과는 HANDOFF를 확인한다.
설치·시작·재사용은 [Docker 문서](../docker/README.md), 배포 게이트는
[docs/06](06_deployment_jetson.md), 작업 분담은 [docs/14](14_pc_jetson_workplan.md)를 따른다.

## 3. 제어와 물리 계약

현재 연구는 FxLMS/FxNLMS 기준선과 인과적 DNN, 경로 추정·계수 전달형 제어를 함께 다룬다.
저장소의 `HybridEngine`은 한 Jetson 안의 DNN+FxNLMS 비교용이며 외부 DSP 결합 구현이 아니다.
온라인 S/F 추정·피드백 보상·학습된 계수 생성의 구현 및 검증 완료를 가정하지 않는다.

플랜트의 극성은 **`e = d + S·y`**다. 측정 FIR에 포함된 극성에 추가 부호 반전을 하지 않는다.
학습·런타임은 S의 지연과 스레드 핸드오프를 일치시키고, RIR에 이미 포함된 음향 온셋을
중복 계산하지 않는다. digital-ref의 재생 FIFO lead와 acoustic-ref의 마이크 선행 시간은
서로 다른 계약이다. 모델은 미래 입력을 참조하지 않으며 스트리밍과 오프라인의 수치 등가성을 유지한다.

기존 기록의 Jetson 경로 총지연 **35.854 ms**, REF 기하선행 **2.915 ms**, S 신뢰대역
**150–600 Hz**는 최신 현장 재측정값이 아니다. Docker·GPU 실행 성공이나 1000–1600 Hz 목표
설정만으로 지연 문제와 고역 경로 검증이 해결되지 않는다. 가진 대역을 경로의 검증 대역으로 대체하지 않는다.
자세한 지연·인과성은 [docs/01](01_physics_limits.md), acoustic 제어 계획은
[docs/13](13_acoustic_hybrid.md), 계수 전달형 연구는 [docs/15](15_prepared_fir_research.md)를 따른다.

## 4. 데이터와 평가

원본은 공식 출처·checksum·라이선스와 함께 관리한다. PC Docker의 임시 다운로드는 허용하며
Drive 파일 ID·크기·업로드 확인·정리 receipt를 남긴 뒤 해당 PC 원본을 삭제한다.
실패·미확인 업로드 원본이나 완전성을 모르는 기존 Drive 자료를 삭제하지 않는다.

MIMII DG fan은 **train-only 학습 보조**다. validation/test에서 제외하고 다른 소스의 상대
비율을 재정규화한다. 공식 split·domain·section 메타데이터를 보존하되 section을 독립 원녹음
ID로 가정하지 않는다. 알려지지 않은 그룹을 가짜 ID로 채우거나 합성 QA만으로 실제 데이터 준비를 선언하지 않는다.
준비 절차는 [docs/16](16_drive_acoustic_preparation.md)을 따른다.

평가는 저역·우선 고역·전체 대역과 소스별 음성·음악·환경음 성능을 함께 본다.
미평가·실패 소스를 0 dB나 성공으로 세지 않는다. surrogate 플랜트와 합성 회귀 결과는
표현·구현 검증이며 물리 감쇠 성능이 아니다. 목표별 지표와 판정 기준은
[docs/07 §0](07_evaluation_protocol.md)을 따른다.

## 5. 완료를 구분하는 검증 단계

1. **환경:** 실제 Jetson Docker에서 PyTorch CUDA·cuDNN, ORT 1.18.1, TensorRT 실행을 확인한다.
   `check_jetson_stack.py`의 작은 Conv1d는 무오디오 설치 진단용이며 ANC 학습모델이 아니다.
2. **프로젝트 모델:** 실제 산출물의 reference mode·lead·플랜트 조건을 확인하고 오프라인↔
   스트리밍·ONNX 등가성과 추론 지연을 측정한다.
3. **현장:** REF/ERR 입력, S/F 경로·신뢰대역·실제 선행 시간·I/O 지연을 확인하고 독립
   OFF→ON→OFF 녹음으로 대역별·소스별 감쇠를 판정한다.

기본 컨테이너는 오디오 장치를 노출하지 않는다. 스피커 출력이 필요한 현장 검증은
**사용자 입회·볼륨 최소·ANC OFF 시작** 조건과 [docs/14](14_pc_jetson_workplan.md)의 절차를 따른다.
현재 환경 준비와 무오디오 검증은 실제 덕트의 저역·고역·음성·음악 감쇠 검증을 완료한 것이 아니다.
